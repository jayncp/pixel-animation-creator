# 全流程像素角色动画 Skill

可从文字、普通参考图、像素参考图，或已经完成的任意制作阶段接入，产出像素角色形象、多视角参考和动画。版本与变更见 [CHANGELOG](CHANGELOG.md)。

本仓库交付的是制作方法与验证工具，不是专用训练模型，也不保证一次生成即达到最终质量。它要求执行 agent 自主研究、制作、看图、发现问题、修复并再验收；缺少生图、播放器、原生编辑器等能力时，必须说明具体缺口，不能把未做的步骤记作通过。

## 安装

skill 位于 [`skills/pixel-character-animation/`](skills/pixel-character-animation/SKILL.md)，入口是其中的 `SKILL.md`。

- Claude Code：`/plugin marketplace add jayncp/pixel-animation-creator`，再 `/plugin install pixel-character-animation@pixel-animation-creator`。
- 支持 Agent Skills 的客户端：`npx skills add jayncp/pixel-animation-creator`。
- Codex 或其他客户端：把 `skills/pixel-character-animation/` 复制到项目的技能目录（如 `.agents/skills/` 或 `.claude/skills/`）。先检查是否已有同名技能，不覆盖未知文件。
- Claude.ai：上传 skill 目录的 ZIP（`cd skills && zip -r pixel-character-animation.zip pixel-character-animation`）。

不需要全局安装或修改账号设置；随附脚本需要 Python 3.10+ 和 Pillow（见 skill 目录的 `requirements.txt`）。工具适配与项目内 MCP 模板见 [`tool-adapters.md`](skills/pixel-character-animation/references/tool-adapters.md)，配置文件只是模板，不会自动运行或注册。仓库不含工具二进制、API 密钥、账号凭据或私有角色图像。

## 怎么用

可以从这些地方开始：

- 只有文字：先用可用的生图能力建立形象，再整理为目标尺寸的像素画。
- 普通参考图：保留辨识特征，重新组织像素块、色板和轮廓，不只是缩图。
- 像素参考图：保留原画设计和网格；更大的交付尺寸用整数倍导出，换网格才重画；按需要补角度。
- 已有多角度图、动画草稿、只修边缘或只导出：直接接入相应阶段，不强迫从头做。

尺寸分三层：形象参考图确定像素网格，一格就是一个像素；动画画布可以随内容变化，人物颗粒度不变；导出时按整数倍放大，例如 128 画布导出 256，网格不变。改用更细或更粗的网格都要重画：变细是增加细节，变粗是压缩，必要时换画法。继续旧项目时保留已有网格。各项默认值和可选项见下一节。

可以这样提出任务：

> 使用这个 skill，把以下描述做成 128×128 画布的像素角色多角度参考，导出 2 倍，暂时不做动画。

> 使用这个 skill 和已有项目，先读取实际素材和项目恢复文件，为角色设计一次蓄力后快速释放的法术动作，自己调查参考、分析节奏、制作并逐帧修复。不要改动冻结的原图。

> 使用这个 skill，只修第 18 帧附近尾巴连接处的脏像素，不改时间轴和人物设计。

skill 保存通用方法与工具；角色项目另外保存原图、身份特征、多视角、时间轴、图层、动作和最终索引（`START_HERE.md`、`project_resume.json`）。在新对话继续时，同时提供 skill 和角色项目，让 agent 先读项目的恢复文件。

## 默认值与可选项

下面各项都有默认做法，不声明也能完成。如果和实际用途不同，最好在“何时声明”一列的时机说明。

| 项目 | 默认 | 可选 | 何时声明 |
| --- | --- | --- | --- |
| 像素网格（人物颗粒度） | 跟随像素参考图的原网格，或你指定的尺寸；都没有时每个视角 256×256 画布 | 任意尺寸；要求更细（加细节）或更粗（压缩，可换画法）都会重画 | 建立形象之前 |
| 动画画布 | 随动作内容扩展，人物不缩小 | 固定画布，例如引擎的格子尺寸 | 开始动画之前 |
| 导出倍数 | 1×；要求的交付尺寸更大时取整数倍 | 指定倍数 | 导出之前 |
| 导出放大方式 | Scale2x（3× 用 Scale3x，4× 用两次 Scale2x，其他倍数用最近邻） | 直接导出：最近邻，每个像素变成 N×N 色块，形状完全不变；MMPX：更好地保留小形状和尖角 | 导出之前 |
| 参考视角 | 完整参考集为正面、三分之四、侧面、背面；做动画时只补动作需要的视角 | 指定视角，或俯视、等距等镜头 | 建立参考集之前 |
| 帧数与时长 | 按动作需要，没有固定上限 | 引擎的帧数或时长限制 | 开始动画之前 |
| GIF 循环 | 循环播放 | 只播一次；一次性动作跳回原位时声明为 cut | 导出之前 |
| 透明 | 二值透明，不用半透明 | 半透明的柔和特效，另交无损 RGBA（GIF 表达不了半透明） | 开始做特效之前 |
| 角色与特效 | 分层交付，特效按在角色前后分层 | 只要合成后的单层图 | 交付之前 |
| 描边与画风 | 跟随原图；没有原图时由 agent 选择并标注 | 指定无描边、黑描边、抖动等 | 建立形象之前 |
| 动作研究 | 在线查找动作参考 | 提供自己的参考，或不联网 | 开始动作之前 |
| 前摇与特效强度 | 按任务描述决定 | 说明用途和夸张程度：玩家普攻通常不要前摇，展示技能可以蓄力 | 开始动作之前 |
| 朝向 | 按动作选一个视角和朝向 | 另画反方向；游戏用镜像翻转时，单侧部件会换边、光源会反向 | 开始动画之前 |
| 生图 | 使用当前环境可用的生图能力 | 不用生图，或不允许上传私有图片 | 开始之前 |
| 交付文件 | PNG 帧、GIF、sprite sheet + JSON、可编辑源或标明的分层替代、项目记录 | 指定格式，例如原生 Aseprite 文件 | 交付之前 |

对实际使用影响较大的几项：

- **默认 256×256 画布颗粒很细。** 每帧要保持一致的像素很多，制作和逐帧检查都更慢。做游戏小精灵时，最好一开始就给出尺寸，例如 48×48 或 64×64。
- **只写一个尺寸时，它可能指网格、画布或导出尺寸**，agent 会记录自己的理解。给了像素参考图时，更大的尺寸通常靠导出倍数实现。尺寸不是整数倍时（例如 96 的原图要 256），会先把画布扩到能整除的大小（128 画布导出 2 倍），或者先问你。
- **Scale2x 让斜线台阶更平滑，但会把很小的形状磨圆**，比如小拳头、刀尖。需要和引擎像素严格对齐，或想保持原样方块时，选直接导出。
- **循环 GIF 的首尾衔接也按动作检查。** 一次性动作要么设计成能接回开头，要么声明为 cut。
- **二值透明在任何背景上边缘都干净，但特效不能半透明淡出**，只能靠变暗、变薄、碎开来消散。

## 工作流

输入与已有阶段检查 → 像素形象与必要的多视角 → 动作资料研究与比例适配 → 关键姿势和节奏 → 选择性补帧与完整动画 → 身份、边缘、逐帧与播放验收 → 可编辑源文件和导出 → 可恢复的项目记录。

这不是必须从头执行的流水线。Python 工具负责清单与路径检查、帧/颜色/透明度和封闭透明孔审计、轨迹诊断、联系表、GIF 和图集导出；它们不决定关键姿势、不自动修脏像素，也不能判断自然度。逐帧看图和 1× 播放不能省略，候选交付前还要请独立复审者看实际图片。
