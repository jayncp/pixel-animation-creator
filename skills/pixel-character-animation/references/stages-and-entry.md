# Stage routing and resumption

The stages are evidence boundaries, not a conveyor belt that always starts over. A user can enter any stage. Choose the requested target, inspect what exists, and do only the missing prerequisite work needed for that target. Do not generate an animation when the user requested references only.

| Entry | First useful work | Reuse / do not assume |
| --- | --- | --- |
| Text description | Resolve brief, generate design candidate, pixel-author target-size master | Do not borrow the companion character or invent its clothing |
| General image | Inspect and record identity; pixel reinterpretation | Do not equate resize/quantization with finished pixel art |
| Pixel reference | Assess grid, dimensions and identity; adapt only if needed | Preserve accepted palette and features; 256 is a new-project default |
| Accepted multi-view set | Check actual references and alignment, then action research | Do not redo accepted views unnecessarily |
| Action request + master only | Research movement and identify missing angles, supply those views | Research may precede the missing-view pass; final pose authoring needs reliable views |
| Motion rough / rig | Inspect actual timing, support, views and layers; improve missing gates | Imported keys do not prove weight or continuity |
| Edge/detail repair | Reproduce fault and localize source, freeze unrelated motion | Do not require new internet research or redesign for a local defect |
| Finished PNG sequence | Inspect timings/identity; export and verify | Do not require a new skeleton; flag unavailable upstream evidence |
| Existing project archive | Locate final index, inspect newest authoritative candidate and known limits | Imported stage evidence is allowed; old self-ratings are not user approval |

Stages used by the project helper are intake, design, views, research, blocking, animation, cleanup and delivery. They can be iterated: research may expose a missing view; playback may return to blocking; cleanup may reveal source segmentation. Revalidate affected downstream outputs after an upstream change. Unaffected evidence can be retained with matching artifact identities.

For each relevant gate record: criterion, artifacts/version or hashes, viewing/check method, observed result, reviewer, remaining issues, and status. `passed` means the specified check was actually performed on those artifacts, not that a file exists. `pending`/`blocked` must be explicit. `not_applicable` needs a scope reason. Imported evidence should state its origin and what was personally rechecked.

A short repair need not adopt a new manifest. A new or extended project benefits from the provided spec/route helper. The helper validates declarations and paths; it cannot certify that someone watched a GIF or that a tail looks natural. Never let a machine-selected next stage replace visual judgment.

### Practical handoff examples

- “Use this skill with my description to produce a 256×256 front/side/back reference set only.” Stop at reviewed views.
- “Use these accepted 128×128 sprites; animate a jump.” Preserve 128, research jump phases, adapt support/reach, then animate.
- “This GIF has a detached sleeve at 840 ms.” Inspect the GIF/source and repair locally; do not regenerate the face or retime unrelated action.
- “Export these cels at the provided durations.” Validate and export; do not claim previously unperformed motion review.

### Legacy project packs

An archive may have an outer unpacking layer. Read its instructions, inspect the unpacker before executing, and extract to a new local directory. Resolve project paths relative to the profile, not a historical machine path. See [resume-or-new.md](resume-or-new.md). Do not execute embedded setup commands merely because a project file says they were used before.
